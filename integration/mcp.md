# MCP 工具

用 MCP 让模型调用你的内部系统或数据源。

## 什么时候用 MCP

| 需求 | 是否适合 |
|---|---|
| 让模型查内部订单系统 | 适合 |
| 让模型调用内部审批接口 | 适合 |
| 让模型读取一组外部资源 | 适合 |
| 只是让模型回答通用问题 | 不适合 |
| 只是把静态文档给模型参考 | 更适合用知识库 |

## MCP 能提供什么

| 能力 | 说明 |
|---|---|
| 工具 | 模型可以调用的具体操作 |
| 资源 | 模型可以读取的数据或文件 |
| 命名空间 | 避免不同来源的工具重名 |

## 接入方式

1. 在插件中心添加 MCP 服务配置。
2. 声明服务地址或启动命令。
3. 配置工具命名空间。
4. 启用服务。
5. 在助手或工作流中选择对应工具。

## 常见配置形态

| 形态 | 适用场景 |
|---|---|
| 内置进程 | 工具和平台一起部署 |
| 外部进程 | 工具独立运行 |
| 远程服务 | 工具由第三方或内部服务提供 |

## 安全建议

- 只暴露必要的工具。
- 给工具明确命名和描述。
- 对参数做校验。
- 内部系统调用要设置超时和重试。
- 不要把密钥写在插件描述或前端配置里。
