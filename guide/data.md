# 业务数据

表单和流程跑起来之后，真正沉淀下来的就是业务数据。

## 它解决什么问题

| 问题 | 平台能力 |
|---|---|
| 表单提交后数据去哪了 | 统一存储为业务数据 |
| 怎么按条件查一条记录 | 列表查询和筛选 |
| 怎么改一条业务记录 | 支持查看和编辑 |
| 流程或智能体能不能用这些数据 | 可作为流程输入或工具数据源 |

## 数据从哪里来

| 来源 | 说明 |
|---|---|
| 表单提交 | 用户填写并提交后生成记录 |
| 流程节点 | 流程执行过程中写入或更新数据 |
| 外部系统 | 通过 API 或集成工具写入 |
| 批量导入 | 从文件或数据集导入 |

## 常用操作

| 操作 | 说明 |
|---|---|
| 查询列表 | 按条件查看一批业务数据 |
| 查看详情 | 打开单条记录，查看完整字段 |
| 新增 | 手工创建一条业务数据 |
| 编辑 | 修改已有记录 |
| 删除 | 删除不再需要的数据 |

## 和表单的关系

表单定义的是“数据长什么样”。

业务数据记录的是“用户实际填了什么”。

因此：

1. 先在 [表单与页面](./forms.md) 里定义字段和校验。
2. 用户提交表单。
3. 平台保存业务数据。
4. 管理员或业务人员再查询和维护这些数据。

## 和流程的关系

流程决定的是“数据如何流转”。

例如：

```text
员工提交请假单
  ↓
生成一条请假业务数据
  ↓
流程按请假天数选择审批路径
  ↓
审批结果回写业务数据
```

## 和智能体的关系

智能体可以读取业务数据作为上下文，也可以在工作流中处理业务数据。

常见场景：

| 场景 | 智能体做什么 |
|---|---|
| 报销审核 | 读取报销单字段，判断是否符合规则 |
| 工单分类 | 根据用户描述自动分类 |
| 数据补全 | 从文档中提取字段并补全记录 |
