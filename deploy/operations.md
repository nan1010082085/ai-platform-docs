# 运维

让部署环境保持可用、可观测、可恢复。

## 日常检查

| 项目 | 方法 |
|---|---|
| 服务是否可用 | 访问健康检查接口 |
| 数据库是否正常 | 查看连接状态和磁盘占用 |
| 模型是否可用 | 发起一次测试对话 |
| 外部 API 是否正常 | 触发一次测试工作流 |
| 日志是否有异常 | 检查错误和超时记录 |

## 日志

建议至少保留：

| 日志 | 用途 |
|---|---|
| API 访问日志 | 排查请求失败 |
| 工作流执行日志 | 定位节点失败 |
| 模型调用日志 | 分析耗时和错误 |
| 系统错误日志 | 发现服务异常 |

不要在日志中记录完整密钥、身份证件或其他敏感原文。

## 备份

至少备份：

- 数据库
- 上传文件
- 环境配置
- 插件配置

建议：

| 项目 | 频率 |
|---|---|
| 数据库 | 每天至少一次 |
| 文件存储 | 每天或每次重要更新 |
| 配置 | 每次变更后 |

## 升级

1. 阅读更新说明。
2. 备份当前数据。
3. 在测试环境先升级。
4. 验证核心功能。
5. 再升级生产环境。
6. 升级后观察日志。

## 常见故障

| 现象 | 先检查 |
|---|---|
| 页面打不开 | 前端进程、反向代理、HTTPS 证书 |
| API 全部失败 | 后端进程、数据库连接 |
| 模型无响应 | 模型服务、网络、API Key |
| 工作流卡住 | 是否在等待人工确认 |
| 磁盘快速增长 | 日志、上传文件、数据库 |
