# 插件开发

开发一个可以安装到平台里的扩展包。

## 插件可以包含什么

| 类型 | 作用 |
|---|---|
| 专家 | 定义一种擅长领域 |
| 技能 | 给专家补充固定能力或规则 |
| 工具 | 让模型调用一个具体操作 |
| MCP 服务 | 接入一组外部工具或资源 |

## 基本结构

一个插件包通常包含：

```text
my-plugin/
├── manifest.json
├── experts/
├── skills/
├── tools/
└── mcp/
```

不是每个目录都必须存在。你只需要放当前插件用到的部分。

## 开发步骤

1. 创建插件目录。
2. 编写 `manifest.json`。
3. 按需添加专家、技能、工具或 MCP 配置。
4. 本地启用插件。
5. 在助手或工作流中测试。
6. 打包成插件包。
7. 分发或安装到目标环境。

## 专家配置示例

```json
{
  "id": "custom.contract",
  "name": "合同专家",
  "description": "擅长合同条款提取和风险提示",
  "systemPrompt": "你是合同审核助手，只回答合同相关的问题。",
  "enabled": true
}
```

## 工具命名

推荐使用：

```text
{domain}__{action}
```

例如：

```text
crm__query_customer
erp__create_order
```

这样多个插件的工具不容易冲突。

## 测试清单

- 插件可以正常加载。
- 启停后能力同步生效。
- 专家能被正确选中。
- 工具参数校验有效。
- 工具失败时有可读错误。
- 不影响内置插件。

## 安全要求

- 只申请必要权限。
- 不在插件文件中写真实密钥。
- 外部请求设置超时。
- 对用户输入做校验。
- 工具返回内容不要包含无关敏感数据。
