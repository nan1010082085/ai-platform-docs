> 日期：2026-07-24

## 〇、设计语言基线（所有新界面必须遵循）

经核实现有 UI 已形成稳定范式，新功能严格对齐：

| 范式 | 现有参照 | 新界面要求 |
|---|---|---|
| 标题栏 | `PageHeader`（标题+副标题+右侧 actions slot） | 所有新视图必须用 PageHeader |
| 布局 | 调试类用「左输入 / 右结果」双列（WorkflowDebugView）；管理类用「顶栏+卡片+表格」（RagKnowledgeBase/AiMonitorView） | 按场景选对应布局 |
| 图标 | `AppIcon` + `iconRegistry.ts` 已注册名（禁止 el-icon/编造名） | 新图标先注册再使用 |
| 交互 | 快捷 chip（RagSearchPanel）、Ctrl+Enter 执行、空状态引导（图标+文案）、历史列表可回填 | 调试类界面全部复用这套 |
| 设计变量 | `var(--el-*)` + CSS Modules | 禁止硬编码颜色 |
| 导航入口 | 顶导 5 主项（对话/工作流/知识库/插件/监控）+ 设置下拉（模型/嵌入/密钥/路由调试） | 新视图挂到对应下拉 |
| 可交互渲染器 | `ActionProposalRenderer` 已有 approve/reject/modify 范式 + `RendererRegistry` 注册机制 | Artifacts 复用此机制 |

## 一、现状盘点（已具备，勿重复造）

| 能力域 | 已实现 | 对标 |
|---|---|---|
| 工作流 | 23 节点（agent-loop/code-execute/switch/variable-set…） | Dify/n8n |

## 二、六大差距 × 交互设计

### 差距 1：RAG 检索质量（P0）

**现状问题**：`ragService.ts` 无 rerank、无 hybrid 加权、检索调试只有 `RagSearchPanel`（显示分数但看不到 rerank 前后对比、看不到命中 chunk 原文）。

**功能方案**：
- rerank：检索 top-N 后用 reranker 重排（BGE-Reranker/Cohere/Jina，复用 Provider 体系）
- hybrid：语义+关键词加权融合（可配权重），替代二选一 fallback
- 分段策略可配：按段落/固定长度/标点

**交互设计 - `RagDebugView`（新视图，挂知识库页 Tab）**：

```
┌─ PageHeader: 检索调试 | 副标题: 验证召回质量与 rerank 效果 ─── [设置检索参数] ┐
│                                                                                │
│  ┌─ 左列：查询区 ──────────┐  ┌─ 右列：召回对比 ──────────────────────┐  │
│  │ el-input 查询框          │  │ [语义结果] [Rerank 后] [Hybrid]  ← Tab │  │
│  │ 快捷 chip（同 RagSearch） │  │ ┌─ 结果卡片 ──────────────────────┐ │  │
│  │ ─ 参数面板（可折叠）─    │  │ │ 92  ▓▓▓▓▓▓▓▓▓░  分数+进度条    │ │  │
│  │  检索模式: ○语义●Hybrid  │  │ │ 表单名 / 描述                    │ │  │
│  │  Top-K: [10] 滑块        │  │ │ [form] 字段chip 字段chip         │ │  │
│  │  Rerank: ☑启用 模型▼    │  │ │ ▸ 展开看命中 chunk 原文(高亮)    │ │  │
│  │  权重: 语义[0.7]关键词[0.3]│ │ │ ▸ rerank 前排名 #3 → 后 #1 ↑3   │ │  │
│  │  分段策略: ▼按段落       │  │ └──────────────────────────────────┘ │  │
│  │ [检索] Ctrl+Enter        │  │ 共 N 条 | 耗时 320ms | rerank +180ms │  │
│  └──────────────────────────┘  └──────────────────────────────────────┘  │
│                                                                                │
│  ┌─ 检索历史（可回填，同 WorkflowDebug 范式）────────────────────────────┐ │
│  │ "用户注册" → 12条 召回  14:30   "请假审批" → 8条  14:25               │ │
│  └────────────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────────────┘
```

**交互亮点**：
- 三 Tab 对比（语义/Rerank后/Hybrid），同一 query 横向看差异
- 每条结果可展开看**命中 chunk 原文 + 关键词高亮**（现在只看到字段名）
- rerank 前后排名变化用 `↑3`/`↓2` 箭头标注，一眼看出 rerank 价值
- 参数面板可折叠，默认收起（常用用户才展开调参）
- 底部显示检索耗时 + rerank 增量耗时（让用户感知 rerank 成本）

**导航**：RagKnowledgeBase 加 Tab 切换「索引管理 / 检索调试」，检索调试即此视图。

### 差距 2：评测体系（P0）

**现状问题**：无测试集、无离线评测、改了 prompt 不知道好坏。企业不敢上生产。

**功能方案**：
- server 新增 `Dataset` + `Testcase` + `Evaluation` + `EvaluationResult` 模型
- `POST /ai/evaluations/run`：对 workflow/agent 跑一批 testcase
- 评测维度：关键词命中 / LLM-as-judge（用另一模型打分）/ 相似度

**交互设计 - `EvaluationView`（新视图，顶导「监控」区新增「评测」入口）**：

```
│  └────────────────────────────────────────────────────────────────────────┘ │  │
│                                                                                  │
```

- 评测运行实时进度条 + 失败用例即时预览（不用等跑完）
- 数据集支持 CSV 批量导入（企业有历史数据）

### 差距 3：定时触发器（P1）

**现状问题**：trigger 只有 manual/webhook/chat/api，做不了"每天9点跑报表""每小时同步"。

**功能方案**：
- `AgentNodeType` 加 `schedule-trigger`（cron 表达式）
- server 加调度器（node-cron），到点触发执行
- `trigger` 类型加 `'schedule'`

**交互设计 - ScheduleTriggerNodePanel + 调度管理**：

```
节点面板（designer 内，同其他 NodePanel 范式）：

│  Cron 表达式: [0 0 9 * * ?]   ← 可视化输入  │
│  ─ 或快捷预设 ─                            │
│  [每天9点] [每小时] [每5分钟] [工作日] [自定义]│
│  ─ 预览下5次执行 ─                         │
│  ▸ 2026-07-25 09:00:00                     │
│  ▸ 2026-07-26 09:00:00                     │
│  ▸ 2026-07-27 09:00:00                     │
│  ─ 时区: [Asia/Shanghai ▼]                  │
│  ☑ 启用调度                                 │
└────────────────────────────────────────────┘

调度日历视图（挂监控区，新页面 ScheduleView）：
┌─ PageHeader: 调度管理 | [新建调度] ─────────┐
│  ┌─ 日历视图（el-calendar）──────────────┐ │
│  │  7/24  7/25  7/26  7/27 ...           │ │

│  ┌─ 调度列表 ────────────────────────────┐ │

│  └────────────────────────────────────────┘ │
```

**交互亮点**：
- cron 可视化：手写 cron 反人类，提供快捷预设 + **下5次执行预览**（输入即算，避免配错）
- 时区显式选择（跨时区团队刚需）
- 调度日历视图：直观看到"今天有哪些调度要跑"，运行状态实时
- 调度可暂停/恢复（不删除配置）

**导航**：节点面板在 designer 内；调度管理挂监控下拉。

### 差距 4：Artifacts 可交互输出（P1）

**现状问题**：19 渲染器全展示型。但 `ActionProposalRenderer` 已证明可交互渲染器可行（approve/reject/modify）。

**功能方案**：
- agent-loop / llm 节点输出 `artifact` 类型（带 schema：code/json/form/html）
- 用户可编辑后回传，作为下一节点输入
- 复用 RendererRegistry 注册机制

**交互设计 - ArtifactRenderer（新渲染器）+ 编辑闭环**：

```
对话消息内（复用 AiMessage + RendererRegistry）：
┌─ Agent 生成的工件 ────────────────────────────┐
│  📄 类型标签: [代码] [表单] [JSON] [预览]  ←Tab │
│  ┌─ 可编辑区 ────────────────────────────────┐ │
│  │  function generateReport(data) {          │ │
│  │    // 用户可直接在这里改                   │ │
│  │    return data.map(...)                   │ │
│  │  }                                        │ │
│  └────────────────────────────────────────────┘ │
│  [编辑] [复制] [下载]        [回传给 Agent →]   │
└──────────────────────────────────────────────────┘

表单类 Artifact：
┌─ Agent 建议的配置 ────────────────────────────┐
│  报表名称: [月度销售汇总          ]            │
│  时间范围: [2026-07 ▼]                         │
│  包含图表: ☑柱状图 ☐饼图 ☑趋势线              │
│  [确认使用]  [让 Agent 调整]                   │
└──────────────────────────────────────────────────┘
```

**交互亮点**：
- **就地编辑**：不跳页，在对话流里直接改（对齐 Claude Artifacts 体验）
- 多形态 Tab：同一 artifact 可在"代码/表单/JSON/预览"间切换查看
- **回传闭环**：编辑后点"回传"，artifact 内容作为下一条消息上下文，agent 基于修改继续（区别于 ActionProposal 的 approve/reject，这是"修改后继续"）
- HTML/图表类 artifact 支持**实时预览**（复用现有 PdfPreviewCard/ExcelPreviewCard 的预览范式）

**导航**：无新页面，融入 chat 消息流。

### 差距 6：流式中断与恢复（P2）

**现状问题**：只能 cancel，不能"跑到一半纠正方向再继续"。

**功能方案**：
- agent-loop 支持 `interrupt`：暂停 + 推送"等待反馈"事件
- 前端展示输入框，用户反馈后 `resume`

**交互设计 - 中断反馈条（融入 chat 输入区）**：

```
agent-loop 运行中：
┌─ 🤔 Agent 思考中... 第3轮 ─ [⏸暂停] [⏹停止] ─┐
│  正在调用工具: 搜索知识库...                   │
└────────────────────────────────────────────────┘

用户点暂停 → agent 主动请求反馈：
┌─ ✋ Agent 需要你的输入 ────────────────────────┐
│  "我搜到了3个相关表单，你想要哪种风格？"       │
│  [简洁现代] [商务传统] [输入其他建议...]       │
│                                  [继续执行 →] │
└────────────────────────────────────────────────┘
```

**交互亮点**：
- 中断反馈用**独立浮层/卡片**（不混在普通消息里），视觉上区分"需要你行动"
- 反馈选项可由 agent 动态生成（LLM 决定问什么）+ 支持自由输入
- 暂停/继续按钮与现有 stopTest 按钮风格一致

## 三、体验打磨（穿插，低工期高感知）
