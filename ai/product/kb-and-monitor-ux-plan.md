## 二、问题陈述

### 2.1 知识库：运维仪表盘挤占主路径

**现状（`RagKnowledgeBase`）：**

- 布局刻意对齐性能监控：健康度环 + 摘要卡 + 双列面板 + 全宽待索引表
- 建库、检索验证、索引运维、嵌入配置同屏竞争
- 用户感知：不好用、不好看；像运维台，不像资产知识管理

**根因：** 信息架构按「指标堆叠」而非「任务流」组织；与 [nav-and-kb-gaps](./nav-and-kb-gaps.md) 已写明的「资产闭环可运营」方向一致，但 UI 未跟上。

### 2.2 性能监控：独立预警台链路过长

**现状（`AiMonitorView`）：**

- 独立路由 `/monitor`：摘要、预警列表、调用脉搏、专家分布、成本趋势、最近调用
- 排障路径：出问题 → 另开监控页 → 再对照专家 / 执行

**根因：** 指标脱离「这次跑」的上下文；预警成台后易沦为无人看的告警墙。指标能力应保留，**展示位迁到执行上下文**。

## 三、目标信息架构

### 3.1 知识库：按任务分层

| 用户任务 | 界面重心 | 层级 |
|----------|----------|------|
| 管资产知识 | 表单 / 流程覆盖率、过期、一键补齐 | **首屏主叙事** |
| 验证有没有用 | 检索试跑 + 命中预览 | 可折叠或二级 |
| 管文档辅线 | 上传与切片 | **独立入口**，不与资产抢首屏 |
| 运维动作 | 全量重建、批量索引 / 删除 | **次级**，非英雄区 |

**不做：**

- 再堆一层监控式统计卡
- 与 Dify 式通用 KB 拼切片军备
- 用 Seekstone 冒充产品知识库

### 3.2 性能与预警：运行时优先

```text
主路径（日常排障）
  对话回合 / 工作流执行详情
    └── 本次：耗时 · Token · 失败节点 · 慢调用

降权（跨专家汇总）
  设置 → 极简入口（成本趋势、预算、平台级异常）
    └── 不再作为顶导级「性能监控」产品面

明确取消
  独立预警台作为主叙事（AlertList 单独成墙）
```

**不做：**

- 把整页图表简单平移进每个专家页
- 删除后端监控 API（能力保留，UI 收口）

### Phase B — 监控并入运行时（P0）

| 步骤 | 交付 | 主要触点 |
|------|------|----------|
| B1 | 线框：对话消息级 / 执行详情级指标条或抽屉 | `design/chat.md`、`design/workflows.md` |

## 五、约束与边界

| 约束 | 说明 |
|------|------|
| 项目隔离 | 仅改 `ai/`（及 `docs/ai/`）；不改 server 接口契约，除非运行时展示缺字段再单独立项 |
